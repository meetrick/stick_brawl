# Stick Brawl (스틱 브롤)

A serverless, real-time P2P stickman fighting game optimized for mobile web browsers. Built entirely with HTML5 Canvas, Vanilla JavaScript, and PeerJS (WebRTC).

삼국지 영웅 5인이 등장하는 **모바일 웹 기반 실시간 P2P 스틱맨 격투 게임**입니다.
이미지·사운드 파일을 하나도 쓰지 않습니다. 모든 그래픽은 Canvas API(선·도형·베지어 곡선)로, 효과음은 Web Audio API로 코드에서 바로 생성합니다.

## 실행 방법

| 모드 | 방법 |
| --- | --- |
| **방 만들기 (Host)** | 캐릭터를 고르고 `방 만들기`를 누르면 4자리 방 코드가 표시됩니다. `초대 링크 복사`로 링크를 보낼 수도 있습니다. |
| **참여 (Client)** | 캐릭터를 고르고 방 코드를 입력한 뒤 `참여`를 누릅니다. 초대 링크(`?room=CODE`)로 열면 코드가 자동으로 입력됩니다. |
| **연습 (CPU)** | 혼자서 CPU를 상대로 연습합니다. 네트워크가 필요 없습니다. |

라운드(合)는 한쪽이 K.O.되면 끝나고, 승리 횟수(勝)가 누적되며 다음 라운드가 자동으로 시작됩니다.

## 조작

| 동작 | 모바일 가상 패드 | 키보드 |
| --- | --- | --- |
| 이동 | 좌측 하단 `◀` `▶` | `A` `D` / `←` `→` |
| 점프 | 좌측 하단 `점프` | `W` / `↑` / `Space` |
| 공격 (누르고 있으면 연속 공격) | 우측 하단 `공격` | `J` / `Z` |
| 대시 (회피, 무적 판정) | 우측 하단 `대시` | `K` / `X` / `Shift` |
| 판정(Hitbox) 보기 토글 | 메뉴의 `판정 보기` | `H` |

- `touchstart` / `touchmove` / `touchend`에서 `e.touches` 좌표로 버튼을 직접 판정하므로 여러 손가락 입력이 동시에 됩니다. 손가락을 떼지 않고 `▶`에서 `점프`로 미끄러뜨려도 입력이 바뀝니다.
- 공중에서 대시는 착지 전까지 한 번만 쓸 수 있습니다. 대시 도중 상대를 통과할 수 있습니다.

## 캐릭터

| 캐릭터 | 무기 | HP | 특징 |
| --- | --- | --- | --- |
| **유비 劉備** | 쌍고검 (양손 단검) | 1.0× | 밸런스형. 공격 한 번에 판정 두 번(오른손→왼손), 공격 속도 빠름 |
| **관우 關羽** | 청룡언월도 | 1.2× | 이동 느림. 매우 느리지만 뒤→머리 위→앞→아래로 이어지는 넓은 베기, 막강한 데미지. 휘두르는 동안 경직 무시(슈퍼 아머) |
| **장비 張飛** | 장팔사모 (뱀 모양 창날) | 0.9× | 이동 빠름. 앞으로 뛰어들며 찌르는 긴 사거리, 매우 높은 데미지 |
| **조조 曹操** | 칠성보도 | 1.0× | 쿨타임이 짧고 베기 궤적이 넓어 빈틈이 적음. 등 뒤 붉은 망토가 펄럭임 |
| **조자룡 趙子龍** | 애각창 (십자형 창날) | 0.8× | 이동 속도·점프력 최상. 딜레이가 거의 없는 연속 찌르기(위·아래 번갈아 찌름) |

관절은 모두 `Math.sin` / `Math.cos` 기반 절차적 애니메이션과 2관절 IK로 계산합니다. 숨쉬기, 걷기, 공중 자세, 피격, K.O. 쓰러짐, 머리띠·수염·망토 흔들림이 여기에 포함됩니다.

## 동생 핸디캡 모드

방장(Host)의 체크박스 설정이 적용됩니다. 켜면 **나중에 접속한 플레이어(Client)** 가 다음 보정을 받습니다.

- 최대 HP **1.5배**
- 무기 Hitbox(사거리) **30% 확대**. 무기 그림도 함께 길어집니다.
- 피격 Hurtbox **20% 축소**

연습 모드에서 켜면 CPU가 아니라 **플레이어 본인**이 보정을 받습니다.

## 네트워크 구조 (Host-Authoritative)

```
Client ──(패드 입력 60Hz: 누름 상태 + 누름 카운터)──▶ Host
Client ◀──(게임 상태 60Hz: 위치/속도/HP/모션 프레임 + 이벤트)── Host
```

- PeerJS 공용 시그널링 서버로 연결한 뒤, 데이터는 WebRTC DataChannel로 기기끼리 직접 주고받습니다.
- 물리 연산(중력, 착지, 경계, 충돌, 타격, 체력)은 **Host만** 계산합니다. Client는 입력만 보내고 받은 상태를 그립니다(위치 보간 포함).
- 접속하면 `hello`(Client 캐릭터) → `init`(양측 캐릭터 + 핸디캡 여부) 순서로 정보를 교환합니다.
- 채널은 순서를 보장하지 않는(unordered) 방식이라 지연이 적습니다. 오래된 상태 프레임은 버리고, 이벤트(타격·K.O.)는 ID로 중복을 걸러냅니다. 점프·공격·대시는 "누름 횟수 카운터"로 보내므로 짧게 톡 눌러도 입력이 빠지지 않습니다.
- 타격 판정은 화면에 그리는 무기 포즈 그대로 계산합니다. 날 구간을 캡슐로 보고, 이전 프레임 위치와 현재 위치 사이를 보간해 빠르게 휘두르는 궤적까지 판정합니다.

## GitHub Pages 배포

1. 이 저장소를 GitHub에 push 합니다.
2. **Settings → Pages → Build and deployment** 에서 Source를 `Deploy from a branch`로 바꾸고, `main` 브랜치의 `/ (root)`를 고릅니다.
3. 잠시 뒤 `https://<사용자명>.github.io/<저장소명>/` 에서 실행됩니다. WebRTC가 동작하려면 HTTPS가 필요한데, GitHub Pages는 HTTPS로 제공됩니다.
4. 휴대폰에서 열고 **홈 화면에 추가**를 하면 주소창 없이 가로 전체화면으로 실행됩니다(PWA standalone).

## 로컬 테스트

```bash
python3 -m http.server 8000
# 브라우저에서 http://localhost:8000 접속
```

브라우저 탭 두 개를 열어 한쪽은 `방 만들기`, 다른 쪽은 `참여`로 P2P 대전을 시험할 수 있습니다.

## 알려진 제한

- **네트워크 환경:** TURN 서버를 쓰지 않으므로 일부 모바일 데이터망(대칭형 NAT)끼리는 연결이 안 될 수 있습니다. 같은 Wi-Fi에서 가장 안정적입니다.
- **오프라인:** 서비스 워커가 없어 오프라인 실행은 지원하지 않습니다. 연습 모드도 첫 로드에는 인터넷이 필요합니다.
- **화면 회전 잠금:** Android Chrome에서는 게임을 시작할 때 전체화면과 가로 고정을 시도합니다. iOS Safari는 이를 지원하지 않으므로, 세로로 들면 "가로로 돌려주세요" 안내가 나옵니다.
- **방장 탭:** 방장이 앱을 백그라운드로 보내면 브라우저가 연산을 멈추므로 게임도 멈춥니다.

```

script.js      캐릭터·무기 데이터, 포즈/IK, 렌더링, 물리, 타격 판정, 네트워크, 입력, CPU AI, 효과음
manifest.json  PWA 설정 (standalone, landscape)
```
